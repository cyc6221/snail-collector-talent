# 天賦資料

一個 CSV 對應一個分支，一列是一個節點：

| 檔案 | 分支 |
|---|---|
| `left.csv` | 左・資源 |
| `middle.csv` | 中・戰力 |
| `right.csv` | 右・兵種 |

## 更新流程

1. 用 Excel／Google 試算表編輯 CSV，存成 **CSV UTF-8（逗號分隔）**。
2. 執行 `node tools/build-data.mjs`，會產生網頁讀取的 `left.js`、`middle.js`、`right.js`。有格式問題時會指出檔名與列數，且不會更新任何 `.js`。
3. CSV 與 `.js` 一起提交。**不要直接改 `.js`**，下次轉換會被覆蓋。

## 欄位

| 欄位 | 說明 |
|---|---|
| 分支 | 分支名稱，同一檔案內必須一致 |
| 層 | 第幾層，從 1 連續編號；同一層的列（1～2 個節點）填同一個數字 |
| 層門檻 | 本層等級合計 ≥ 此值，下一層才解鎖；可留空（預設 5），同一層填一致即可 |
| 節點ID | 唯一識別碼（跨檔案也不可重複）：英文字母開頭，只能用英數、底線、連字號。使用者的配點以 id 記錄，**發佈後請勿更改** |
| 名稱 | 節點名稱 |
| 顏色 | 藍／紫／橘 |
| 每級消耗 | 整數 |
| 最高等級 | 整數，可留空（預設 5） |
| 效果 | `屬性 \| 每級數值 \| 單位`，多個效果用分號 `;` 隔開，例：`時光機探索產量 \| 5 \| %; 時光機容量 \| 5 \| %`。單位可留空，數值可為負 |
| 備註 | 顯示在卡片上的小標籤，可留空 |
| 點滿解鎖下一層 | 填「是」表示這個節點必須**點滿**，才能解鎖下一層；有節點標記「是」的那一層，只看這些節點，同層其他節點點多少都無關，「層門檻」也不再適用。留空＝一般規則（整層合計達門檻）。例：第 14 層橘色節點填「是」，紫色節點留空 |

> 使用者的瀏覽器只存配點與擁有點數，資料每次都直接讀取這些檔案，所以提交後所有人下次開啟就是最新版。配點以節點 ID 記錄，因此不要更改已發佈的 ID，否則該節點的配點會消失。

## 額外樓層（`top.csv`，第 16 層以後）

接在三個分支的最後一層之下，用同一個檔案描述。一列一個節點，格式與分支 CSV 不同：

| 欄位 | 說明 |
|---|---|
| 樓層 | 第幾層，從「各分支最高層 + 1」開始連續編號（目前是 16、17…） |
| 分支 | 這個節點屬於哪個分支：填「左」「中」「右」（也可填完整分支名）。**紅色節點可以留空**，表示不屬於任何分支 |
| 節點ID | **可留空**（自動產生，見下方）。要手填的話規則同分支節點，所有檔案之間都不可重複 |
| 名稱 | 節點名稱 |
| 顏色 | 紅／藍／紫／橘。「紅」是特殊的天賦類型，不是點數顏色 |
| 每級消耗 | 一般節點填整數（用節點的顏色）；可以同時花多種點數時寫成 `藍 5; 紫 5; 橘 5`，**紅色節點一定要這樣寫** |
| 最高等級 | 整數，可留空（紅色節點預設 3，其他預設 5） |
| 效果 | 同分支 CSV：`屬性 \| 每級數值 \| 單位`，多個用分號隔開 |
| 解鎖來源節點 | **可留空**（見下方預設規則）。要看哪些節點的等級，填節點ID，多個用分號隔開（可以是分支節點，也可以是更低樓層的額外節點） |
| 解鎖所需等級合計 | **可留空**（見下方預設規則）。上面那些節點的等級加起來要達到多少，才能點這個節點 |
| 備註 | 顯示在卡片上的小標籤，可留空 |

### 預設規則（留空時自動套用）

第 16 層以後的樓層規則幾乎一樣，所以那三個欄位通常不用寫：

- **節點ID**：紅色節點是 `red-樓層a`（如 `red-16a`）；分支節點是 `分支前綴-樓層a`（如 `res-17a`）。同一層同一分支有兩個節點時，紫色是 `a`、橘色是 `b`（如 `res-18a` 紫、`res-18b` 橘）。
- **解鎖來源節點**：上一層「同一分支」的所有節點；如果上一層沒有同分支的節點（例如上一層是紅色節點），或這個節點是紅色（不屬於分支），就用上一層的全部節點。
- **解鎖所需等級合計**：5，但不超過來源節點「最高等級」的總和（例如來源是 1 個最高 3 級的紅色節點，就是 3）。

目前第 16～20 層全部都符合預設，`top.csv` 裡這三欄都是空的。**只有規則不同的節點才需要手動填**，填了的欄位一律優先。如果自動產生的 ID 與其他節點重複，或找不到可當來源的上一層節點，轉換工具會指出是哪一列並請你手動填寫。

套用預設後的結果（也就是「第 15 層是特例，之後都固定」的樣子）：

| 樓層 | 內容 | 解鎖 |
|---|---|---|
| 16 | 1 個紅色節點 | 第 15 層（三分支）合計 5 |
| 17 | 三個分支各 1 個藍色 | 紅色節點（最高 3）合計 3＝點滿 |
| 18 | 各分支 1～2 個節點 | 各分支自己第 17 層合計 5＝點滿 |
| 19 | 三個分支各 1 個橘色 | 各分支自己第 18 層合計 5 |
| 20 | 1 個紅色節點 | 第 19 層（三分支）合計 5 |

- 每一層，要嘛只有**一個**不屬於任何分支的節點，要嘛每個分支各最多 **2 個**節點（和分支的層一樣）；轉換工具會檢查。
- 連線畫法依解鎖來源決定：來源在其他分支（例如第 16 層）會畫成匯合或分岔的連線；每個節點的來源都在自己的分支（例如第 18 層，來源是各分支自己第 17 層的節點）則各分支各自連線。
- 屬於某個分支的額外節點，效果會算進那個分支的「能力加總」，點數也計入該分支的「全點滿需要」；不屬於任何分支的節點（紅色），在「能力加總」裡獨立一項「紅色天賦」。
- 所有額外節點花的點數都計入頂部的已用點數。
- 降級若會讓已有配點的後續節點失去解鎖，必須先減少後面的節點。
- 這份檔案是選用的：沒有 `top.csv` 時，網站照常運作，只是沒有第 16 層以後。
